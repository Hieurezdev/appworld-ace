## COMMON MISTAKES AND CORRECT STRATEGIES

[cms-00026] Mistake: Assuming all liked songs should be rated without verifying they are part of the user's playlist library
- Correct strategy: Always verify that a song is both liked and present in the user's playlist library by performing a set intersection. This prevents over-rating songs not in the user's playlists and ensures data integrity.
[cms-00030] Mistake: Assuming all liked songs are valid for rating without verifying their presence in the playlist library
- Correct strategy: Always perform a set intersection between liked songs and playlist songs before any rating update. This ensures only songs that are both liked and part of the user's playlist library are processed, preventing false positives and maintaining data integrity.
[cms-00037] Mistake: Using a set intersection between liked songs and library songs when the task requires songs that are in the library but not liked
- Correct strategy: For tasks that require rating songs not liked, compute the set difference (library songs minus liked songs) to identify eligible songs. This ensures only songs present in the library and not previously liked are processed, preventing false positives and maintaining data integrity.
[cms-00042] Mistake: Treating 409 conflicts as a reason to skip processing a song in the set difference (library minus liked)
- Correct strategy: Even if a 409 conflict occurs, the song must still be processed. The task requires a 1-star rating for all songs in the library that are not liked, regardless of their current rating. Log the 409 error and continue to the next song. This ensures that every song in the set difference is accounted for and updated to 1 star, preventing missing entries in the final output.
[cms-00045] Mistake: Applying a default high rating (e.g., 5 stars) to songs in a liked album library when the task specifies a different rating (e.g., 4 stars)
- Correct strategy: Always match the rating value explicitly stated in the task. For example, if the task says 'give a 4-star rating', update the rating to 4, not 5. This prevents incorrect rating updates due to misalignment between task instructions and playbook defaults.
[cms-00092] Mistake: Using a simple presence check for director annotations without verifying the immediate preceding line as a movie title.
- Correct strategy: Before extracting a movie title, verify that it is on a line starting with a capital letter and is immediately followed by a line that starts with ' - director: [director_name]'. This ensures only valid, relevant movies are included in the response and prevents structural misreads that lead to incorrect or incomplete data extraction.
