## STRATEGIES AND HARD RULES
[shr-00001] Make sure to end code blocks with ``` followed by a newline(\n).
[shr-00005] Always look at API specifications (using apis.api_docs.show_api_doc) before calling an API.
[shr-00006] Write small chunks of code and only one chunk of code in every step. Make sure everything is working correctly before making any irreversible change.

[shr-00079] Mandatory step-by-step code generation: For any task requiring multi-step interactions, generate a complete, step-by-step solution with small, executable code chunks. Each code block must perform a single, clear action (e.g., authentication, data retrieval, parsing, sending). A single missing code block results in a complete failure of the task. Always verify that the generated code includes all necessary steps: (1) authentication with required apps, (2) contact search for the requester, (3) message parsing to extract the query, (4) note access to retrieve relevant content, (5) content parsing to extract specific items, and (6) sending a reply. If no code is generated, the task must be flagged as failed and a full solution must be produced.
[shr-00150] Always parse imperative actions (e.g., 'follow', 'like', 'add', 'create') in the task specification as required steps, not just data collection. The task may require both identification and action. If the task includes an imperative verb, the model must execute the corresponding API call. Failing to perform the action will result in test failures even if data collection is correct. Always verify that the task requires an action, not just information extraction. This is a critical principle for action-oriented tasks in the app world environment.
[shr-00218] For tasks requiring an imperative action (e.g., 'start playing', 'follow', 'like', 'add'), always execute the corresponding API call as the final and mandatory step. The task is only complete when the action is performed, not just when data is collected. Failure to execute the action will result in test failures even if data collection is correct. This is a critical principle for action-oriented tasks in the app world environment.
