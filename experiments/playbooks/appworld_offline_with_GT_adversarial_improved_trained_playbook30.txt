## COMMON MISTAKES AND CORRECT STRATEGIES

[cms-00027] Critical mistake: Incorrectly assuming all liked songs should be rated
- Do not process all liked songs directly. The task specifically requires rating only songs that are both in the user's library and have been liked.
- This is a fundamental error in data scope identification and filtering logic. Always verify the task's data source and scope before assuming equivalence between collections.
- The correct approach is to find the intersection of songs that are both in the library and liked, which is a critical filtering step that must be explicitly implemented.
[cms-00029] Critical mistake: Omitting required API parameters like access_token
- Do not assume that an API call can be made without an access token or other required parameters. Always verify the API's parameter list using `apis.api_docs.show_api_doc()` before calling.
- For APIs like `review_song`, `show_song`, or `show_liked_songs`, the access_token parameter is required and must be explicitly passed in every call. Missing it will result in a 401 Unauthorized error, regardless of the correctness of the logic.
- This is a common but subtle error that leads to execution failures and must be explicitly prevented in the playbook.
[cms-00031] Critical mistake: Failing to handle 409 Conflict errors during review operations
- Do not treat a 409 Conflict error as a task failure when calling `review_song`. A 409 Conflict typically means a review already exists for that song, which is not an error in the task logic.
